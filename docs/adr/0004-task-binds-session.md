# 0004 Task 綁在派出去的那個 Session，不綁工作目錄

**Status**：accepted（2026-09-25）

最直覺的做法是在工作目錄（worktree 根目錄）放一個標記檔，執行機上的全域 hook 看到標記就算追蹤中。任何執行者都不用改就能用，但追蹤的單位變成目錄：人在同一個目錄另開的 Session 停下時，也會通知人、叫醒派工對話。「人自己開的 Session 不觸發」只有在不同目錄時才成立。標記檔一旦被 commit，同一個 repo 的每個 worktree 還會一起被追蹤。

做法：

- Task 只綁調度者派出去的那一個 Session，以及它的接續（不論是誰接的）。同一個目錄裡的其他 Session 一律不算追蹤中。
- Task 從派工開始，只有被關閉才結束。
- Session 退出（正常退出或當掉）算一次停下事件：通知並叫醒，由調度者決定要接回來還是關閉。
- 人插手打字不會自動關閉 Task，之後再停下仍會叫醒。要讓調度者退出，由人關閉 Task。
- 關閉後，那個 Session 和它的接續再停下，不通知也不叫醒；Session 本身繼續跑，不會被關掉。

為什麼：

- 人和調度者操作的是同一批 Session。只有「派出去的那一個」代表調度者在等結果。
- Session 退出常常發生在中途（當掉、不小心關掉、要換參數重開），調度者需要知道，而不是讓 Task 默默結束。
- 關閉是唯一的結束方式，規則只有一條，人和調度者都不必猜 Task 現在算不算數。

代價：

- 派工時要把 task id 交給那一個 Session，也要能認出接續，三種執行者都要做得到。做法見 0005。
- Task 不會自己過期，沒被關閉的 Task 會一直留著，要靠調度者或人收尾。
- 人插手時調度者仍會被叫醒，可能在人正在操作時插話。
